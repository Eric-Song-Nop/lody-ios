## Native originating-row candidate repair

The subsequent Kotlin change records the stable ID only when a navigating row is actually accessibility-focused at activation. While its owner is covered or detached, it retains that identity. On return, the row supplies `setRequestInitialAccessibilityFocus` only while visible to accessibility and no available view already owns accessibility focus. Any chosen focus clears the pending identity, as do a new touch action and removal of the navigating row. It never calls an accessibility-focus action or retries focus assignment. The pre-draw observer is removed on detach; keyboard ownership remains separate.
