# Android 逐 PR 交付清单

日期：2026-09-10。配套[阶段路线图](2026-09-10-android-pr-roadmap.md)和[平台能力契约](../architecture/android-platform-contracts.md)。本文细化执行边界，不改变已有 PR 的完成状态，也不表示候选依赖已在产品中可用。状态、真实 PR 链接和验证报告统一登记在路线图。

## 使用方式

每行是一个实际 PR 的审查单元。已有 PR-00～05b 保持原有边界；后续默认按照表中子编号依次堆叠。后继 PR 的 Git base 是紧邻父分支，能力准入另外按路线图检查。跨阶段提前制作离线 fixture 可以独立进行，产品接线必须等待前置验收。

每个 PR 从现有 kit facade 出发，在正文列出本次涉及的导出、调用方、真实实现和未开放入口。第一方 Kotlin 实现通过同一个 `LodyKitModule` 注册。不能为了让入口编译成功而补空实现。

审查材料随实现提交；证据随实际验证更新。下面的 case ID 沿用路线图，是验收要求，不保证已有同名 runner 命令。可执行参数以 [Android runner 文档](../../apps/mobile/verification/android/README.md)为准。

05b 的基础行验证不等于完整列表通过：动态插入/删除后的滚动锚点、焦点和无障碍需要单独覆盖。触觉 API 返回与物理反馈分开记录，模拟器不能证明真机触感。

06 开始前保存同一份最终 Markdown、预期复制文本和带时间戳的增量输入。至少包含 1,000 条混合历史、顶部补页 100 条，以及等长替换、回退、后置引用定义、延迟图片尺寸、未闭合公式和代码。07 和 16 复用这些输入，避免用更简单的样例掩盖回归。

Enriched 的流式支持是选型依据；字符渐入、跨块选择、列表回收和稳定滚动仍须逐项证明。07b 无法通过时启动可选 X3 对照，08 和 09 的生产聊天接线保持阻塞。

## 每个 PR 的收尾清单

- 在正文列出父 PR、计划编号、本次可观察行为、实际修改范围及仍未开放的入口。
- 记录源码 commit、工作树状态、APK 和 fixture/资产哈希；工程检查、行为断言、视觉复核分别给结果。
- 每项失败保留原因与复现材料；修复后记录新版本结果，不能覆盖旧失败来暗示首次即通过。
- 涉及共享能力时列出受影响宿主和 iOS 回归。文档改动只做格式、链接和依赖审查，不需要重跑原生产品验收。
- 每阶段最后在同一版本执行集成验收，登记缺少的真机、推送或真实账号证据。单个子集通过不解锁整个能力包。
- 更新路线图状态和能力清单；PR 创建、验证通过、CI 通过、合并和发行分别记录。

出现跨账号数据、权威文本丢失、自动重复发送、无界队列/重启或 iOS 核心回归时，当前 PR 必须修复或保持入口关闭；依赖该行为的产品 PR 不继续接线。
