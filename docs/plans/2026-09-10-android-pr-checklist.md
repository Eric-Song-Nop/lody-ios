# Android 逐 PR 交付清单

日期：2026-09-10。配套[阶段路线图](2026-09-10-android-pr-roadmap.md)和[平台能力契约](../architecture/android-platform-contracts.md)。本文细化执行边界，不改变已有 PR 的完成状态，也不表示候选依赖已在产品中可用。状态、真实 PR 链接和验证报告统一登记在路线图。

## 使用方式

每行是一个实际 PR 的审查单元。已有 PR-00～05b 保持原有边界；后续默认按照表中子编号依次堆叠。后继 PR 的 Git base 是紧邻父分支，能力准入另外按路线图检查。跨阶段提前制作离线 fixture 可以独立进行，产品接线必须等待前置验收。

每个 PR 从现有 kit facade 出发，在正文列出本次涉及的导出、调用方、真实实现和未开放入口。第一方 Kotlin 实现通过同一个 `LodyKitModule` 注册。不能为了让入口编译成功而补空实现。

审查材料随实现提交；证据随实际验证更新。下面的 case ID 沿用路线图，是验收要求，不保证已有同名 runner 命令。可执行参数以 [Android runner 文档](../../apps/mobile/verification/android/README.md)为准。

按下面的默认拆分，共 28 个必需 PR，另有 3 个条件触发的优化 PR。主编号 00～17 是能力包；带字母的编号是实际审查单元。已有 PR 保留原边界，进一步拆分时同步更新计数与依赖。

| 阶段 | 实际 PR                          | 阶段结束时可交付的结果                 | 仍受后续门槛约束的能力     |

| B    | 02、03、04                       | 真实 WASM、受控恢复和安全本地恢复      | 授权接线、聊天与发送       |
| C    | 05a、05b、06、07a、07b、08a、08b | 完成选型的原生交互、流式聊天和输入草稿 | 真实 Cloud 读写闭环        |

阶段结束必须在同一版本做集成验证。各 PR 分别通过不能证明组合后没有回归；缺少真机或真实联调证据时，明确保留未完成项，不以模拟器结果代替。

06 开始前保存同一份最终 Markdown、预期复制文本和带时间戳的增量输入。至少包含 1,000 条混合历史、顶部补页 100 条，以及等长替换、回退、后置引用定义、延迟图片尺寸、未闭合公式和代码。07 和 16 复用这些输入，避免用更简单的样例掩盖回归。

Enriched 的流式支持是选型依据；字符渐入、跨块选择、列表回收和稳定滚动仍须逐项证明。07b 无法通过时启动可选 X3 对照，08 和 09 的生产聊天接线保持阻塞。

## 关键能力包的具体实施顺序

以下步骤细化现有审查单元，不增加必需 PR 数量，也不修改完成状态。实现时按各 PR 的开始条件推进；已经有实现的部分先核对证据与契约，只补缺口。

### PR-02～04：先证明真实 WASM，再建立恢复与持久化

1. **02 · 固定资产**：从现有资产生成链路产出 JS、Loro/Flock WASM 和依赖许可证，记录哈希。列出实际用到的浏览器 API、加载路径与桥接消息；离线 fixture 与真实运行时使用同一资产。
2. **02 · 跑通完整数据路径**：Kotlin 创建本地 WebView，等待真实初始化结果，依次执行 bootstrap、增量输入和完整投影输出。随后覆盖拆开的 uint32 大端长度头、payload、压缩输入及桥接分块；逐字段比较投影，不能只检查“加载成功”。
3. **02 · 封住输入与队列边界**：定义单副本 8 MiB 上限、损坏输入和背压结果。保存失败样例与实际错误；尚未完成的投影不得进入 live 状态。
4. **03 · 补生命周期**：在原生侧实现启动/心跳 deadline、generation 隔离和有限重启。分别注入初始化未完成、renderer 退出、后台暂停、替换后旧回调以及主动停止；核对请求结算和订阅清理。
5. **04 · 接安全恢复**：长期凭据进入 Keystore 保护的私有存储，完整显示投影进入 SQLite。先验证离线恢复，再验证重新认证、切换账号和退出；将密钥失效、损坏与迟到写入作为独立失败用例。

阶段交接要同时提供成功投影、故障状态和停止后的资源状态。Sandbox 对照复用这些资产、输入与预期；它只影响可选宿主优化，不改变 WASM 必须交付这一要求。

### PR-06～07b：把“支持流式”拆成可验收的聊天行为

1. **06 · 锁定比较对象**：记录 Enriched RN Android 与 FlashList 候选的确切版本、原生依赖、许可证及工具链兼容结果。库类型留在适配层，消息身份与事件契约采用项目类型。
2. **06 · 建立静态与未完成态对照**：同一消息依次呈现最终 Markdown、逐段未闭合 Markdown、公式、表格、代码和任务列表。逐项记录显示与复制差异；不能用最终态截图证明流式中间态正确。
3. **06 · 放入真实虚拟列表**：加载固定的 1,000 条混合历史、补入 100 条旧消息，并记录挂载、回收与重绑定。将延迟图片尺寸、代码长行和公式高度纳入测量，交付原型缺口表。
4. **07a · 实现流式状态机**：分别维护最新权威文本、显示进度及服务端完成状态。先保证追加、等长替换、回退与尾部完成正确，再加入字符渐入；记录解析调用，证明动画没有逐帧触发全文重解析。
5. **07b · 联合检查选择与滚动**：覆盖用户离开底部、顶部补页、选择期间内容变化、尺寸变化和回收后返回。对每个样例给出锚点结果、选择规则及精确复制文本，不能只凭滚动录屏判断内容正确。
6. **07b · 决定生产路线**：按 README 能力逐项关闭差距。决策只能是直接采用、有界扩展后采用，或触发 X3 并继续阻塞生产接线；记录扩展范围、维护责任和仍缺少的实机性能证据。

Enriched 的流式能力是原型起点。CTRunDraw 对应的渐入效果、系统选择、公式布局及长历史组合质量，各自保留验收结果；一个能力通过不会自动证明其他能力通过。

### PR-10a～11b：先证明写入顺序，再开放发送入口

1. **10a · 固定状态与提交点**：列出 history 保存、durable dispatch pointer 保存、Machine RPC 发出、ACK 到达和回复完成的状态转换。对每个状态明确进程恢复后的展示，以及允许的用户动作。
2. **10a · 注入中断**：分别在保存前、保存后未 dispatch、请求可能送达但未 ACK、ACK 后回复未完成处中断。记录本地持久化内容与实际命令次数；恢复不能自动重复写入。
3. **10b · 接产品输入与回复**：仅在上述故障矩阵通过后连接 composer。覆盖重复点击、页面离开、回复增量、完成和用户主动重试；ACK 只改变送达状态。
4. **11a · 明确附件持有者**：逐步实现系统选择、URI 权限、临时文件、上传与取消。每个文件记录草稿、上传及发送任务的持有关系；失败和退出只能释放自身持有，不能误删仍被使用的文件。
5. **11b · 接创建与首发**：验证创建成功但上传或发送失败的部分成功路径，保留已创建会话身份；正文与附件共同恢复，旧恢复 token 不覆盖用户新编辑。随后逐项接入其余写命令。

阶段 D 收尾使用同一版本走完授权、历史、文本发送、附件、新会话及故障恢复。离线命令计数与专用测试账号的真实联调分别给出证据。

## 控制单个 PR 的范围

默认使用上面的 28 个审查单元。若单个 PR 同时引入新宿主、替换渲染引擎并接通真实写入，必须重新划分范围；这三类变化无法用一份原型证据共同验收。新增子编号时同时修改阶段总览、直接依赖和交接表，保留既有真实 PR 的编号和链接。

- **原型 PR**交付可运行的内部场景、测量和缺口；不顺带开放产品按钮。
- **正确性 PR**在固定输入上解决状态与生命周期问题，失败用例随修复保留。
- **接线 PR**消费已验证契约，重点验收取消、错误、账号隔离和用户可观察结果。
- **发行 PR**验证最终包及升级路径；不能用构建成功代替功能与真机验收。

排期以阶段门槛推进，不预填未经原型验证的人日。PR-06 的结果决定 07 是否需要 X3；真实 WASM 兼容失败阻塞数据路线，不能以 Markdown 已能显示来绕过；Sandbox 对照即使失败，也不阻塞已达标的 WebView 宿主交付。

1. **PR-02 的 WASM 兼容包**：锁定实际资产及哈希，列出需要的 Web API、原生桥接、资源上限和失败结果。PR-03、04 消费同一数据契约；可选 Sandbox 对照复用完整资产，不以简单 WASM demo 代替。

## 每个 PR 的收尾清单

### 单个 PR 的执行顺序

每个审查单元按以下顺序推进。它们是同一个 PR 内的工作步骤，不增加必需 PR 数量；提交数量按实际改动决定。

| 步骤              | 具体工作                                                                                | 退出条件                                                          |
| ----------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1. 固定边界       | 核对能力前置、父分支、涉及的 facade 与宿主；为新增行为登记 fixture 输入、预期和失败结果 | 消费方能据此实现；未实现能力不会被 Android 入口导入               |
| 2. 交付最小行为   | 实现真实原生能力和内部场景，先打通一条完整成功路径，同时实现取消、错误结算和资源释放    | 可以在离线场景中观察真实结果；不以 stub 或固定成功值代替          |
| 3. 补齐边界与验证 | 执行本 PR 的故障、生命周期及受影响宿主矩阵；修复后使用新构建复验，保留原失败证据        | 必需行为、视觉与时序检查分别有结论；共享原生变化完成对应 iOS 回归 |
| 4. 接线与交接     | 仅开放本 PR 获准的入口；更新能力契约、证据索引、下一 PR 消费的样例及未完成项            | PR 描述对应最终实现；前置验收完整后，下游才消费该能力             |

原型 PR 的第 4 步交付内部入口和决策材料；产品接线仍由表中指定的后续 PR 承担。遇到新依赖兼容性失败，先缩小到可复现样例并记录决策，不把未通过部分挪出验收范围。

### 阶段验收记录模板

阶段报告由该阶段的收尾 PR 维护，路线图只链接报告并记录总状态。以下模板用于区分单项通过、组合通过和仍缺少的证据。

```markdown
阶段：A / B / C / D / E / F
收尾 PR：计划编号及实际链接
包含的必需 PR：逐项列出
验证源码 commit / 工作树状态：
APK 哈希 / 资产及 fixture 版本：
设备 / 系统 / WebView provider / 构建类型：

| 门槛                 | 对应用例及证据             | 结果   | 未完成项及阻塞的能力 |
| -------------------- | -------------------------- | ------ | -------------------- |
| 各必需 PR 的行为验收 | 引用报告及实际构建版本     | 待执行 |                      |
| 本阶段连续集成流程   | 同一 APK 的完整操作轨迹    | 待执行 |                      |
| 受影响的前序能力     | 按接口变更回归表选取       | 待执行 |                      |
| 视觉、时序和无障碍   | 分别记录断言与复核         | 待执行 |                      |
| iOS 回归             | 对应共享或原生改动         | 待执行 |                      |
| 真机及真实联调       | 本阶段要求的设备和账号范围 | 待执行 |                      |

阶段结论：验证中 / 验证通过
允许下一阶段接入的能力：
仍关闭的入口及原因：
```

没有适用场景的行写明原因；缺少规定证据的行保留待验证。某个主题、宿主或输入子集通过，只关闭对应项，不能直接将整阶段标记为通过。旧 APK 结果可以保留作为历史基线，但不能证明后来新增的原生资源或行为。

- 在正文列出父 PR、计划编号、本次可观察行为、实际修改范围及仍未开放的入口。
- 记录源码 commit、工作树状态、APK 和 fixture/资产哈希；工程检查、行为断言、视觉复核分别给结果。
- 每项失败保留原因与复现材料；修复后记录新版本结果，不能覆盖旧失败来暗示首次即通过。
- 涉及共享能力时列出受影响宿主和 iOS 回归。文档改动只做格式、链接和依赖审查，不需要重跑原生产品验收。
- 每阶段最后在同一版本执行集成验收，登记缺少的真机、推送或真实账号证据。单个子集通过不解锁整个能力包。
- 更新路线图状态和能力清单；PR 创建、验证通过、CI 通过、合并和发行分别记录。

出现跨账号数据、权威文本丢失、自动重复发送、无界队列/重启或 iOS 核心回归时，当前 PR 必须修复或保持入口关闭；依赖该行为的产品 PR 不继续接线。

## 可直接使用的 PR 正文模板

```markdown

- facade 与调用方：实际 API / View 和开放入口。

### 验证证据

APK / fixture / WASM 资产哈希：
设备 / API / WebView provider / 构建类型：

| 检查               | 实际命令或 case             | 结果   | 证据与限制             |
| ------------------ | --------------------------- | ------ | ---------------------- |

- 未通过项及其阻塞的后续 PR：
```

不适用的检查应写明原因。模板中的“待执行”不是通过结果；创建 draft PR 不改变能力完成状态。文档 PR 只需记录格式、链接和计划一致性检查。
